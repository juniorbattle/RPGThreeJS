# Demo roadmap

Baseline: `main @ 6ff5f4c78b9bacb945b9c20d5ce39d6222b68aa0`. Scope labels are planning controls, not implementation approval.

## DEMO_REQUIRED

1. Revalidate the existing Lion campaign from start through the terminal route in a built production app, including both T0 branches, save/resume boundaries, first and second refuge services, canonical combat, dialogue, Journey, cinematics, VFX, and narrow UI. Record failures and fixes against current source.
2. Keep the T0 production loop's current systems and no-road-combat contract intact. Use the [T0 QA guide](../traversal/QA_GUIDE.md) and select a compact final evidence set.
3. Resolve any actual demo-blocking missing media, content, accessibility, or visual defects discovered by that current run. The mere existence of a historical report does not close a release gate.

## Existing production, with acceptance still to confirm

Campaign topology and saves, T0 Traversal, two interactive refuges, Journey, dialogue, canonical combat, and their current content are implemented. The [demo content map](../content/DEMO_CONTENT_MAP.md) records the source and each uncertainty.

## DEFERRED_UNDECIDED

Playable T1/T3/T4 Traversal, retiring playable T2 in favor of a direct handoff, and converting final refuge to an interactive hub are candidate future work. The current campaign already presents those segments through Journey. No source or approved decision in this baseline establishes that these conversions are required for the demo. [Leg-by-leg audit](../traversal/LEGS_ROADMAP.md).

Before promoting one of these ideas to **DEMO_REQUIRED**, obtain a scope decision, define an acceptance contract, identify art and content dependencies, and authorize the relevant campaign/runtime changes.
